# Визуализатор графа зависимостей (вариант №12)

Практическая работа №2 по дисциплине «Конфигурационное управление».

## Общее описание

Инструмент командной строки для построения и визуализации графа
зависимостей пакетов менеджера Cargo (язык Rust). Готовые средства
получения зависимостей (менеджеры пакетов, сторонние библиотеки) не
используются.

Текущее состояние — **этап 2 (сбор данных)**. Приложение получает из
репозитория Cargo описание заданной версии пакета и выводит все его
прямые зависимости. Построение графа с учётом транзитивности и
визуализация появятся на следующих этапах.

На этапе 1 приложение принимало и проверяло все настраиваемые
параметры и выводило их в формате `ключ=значение`. Этот вывод по
заданию нужен только на этапе 1, поэтому на этапе 2 он заменён выводом
зависимостей; проверка параметров осталась прежней.

## Структура проекта

```
src/
  main.py              точка входа
  depviz/
    cli.py             запуск: вывод зависимостей и ошибок, код завершения
    config.py          разбор опций командной строки и сбор ошибок
    validators.py      проверка значения каждого параметра
    registry.py        чтение прямых зависимостей из индекса Cargo
    semver.py          разбор и сравнение версий SemVer
    testing_repo.py    чтение файла тестового репозитория
tests/                 модульные тесты (unittest)
examples/              файлы тестового репозитория (правильный и с ошибкой)
scripts/               демонстрационные скрипты (.sh и .bat)
run.sh / run.bat       запуск приложения (аргументы передаются дальше)
```

## Описание функций и настроек

### Параметры командной строки

| Опция | Параметр | По умолчанию |
| --- | --- | --- |
| `--package ИМЯ` | имя анализируемого пакета | обязательный |
| `--repo URL\|ПУТЬ` | URL-адрес репозитория или путь к файлу тестового репозитория | обязательный |
| `--mode remote\|test` | режим работы с тестовым репозиторием | `remote` |
| `--version ВЕРСИЯ` | версия пакета | `latest` |
| `--output ФАЙЛ` | имя сгенерированного файла с изображением графа | `graph.svg` |
| `--filter ПОДСТРОКА` | подстрока для фильтрации пакетов | не задана |

Режим `remote` означает работу с реальным репозиторием по URL-адресу,
режим `test` — с файлом тестового репозитория, в котором пакеты
называются большими латинскими буквами. От режима зависят правила
проверки `--package` и `--repo`.

Сокращённые имена опций (например, `--pack`) не принимаются.
`-h`/`--help` выводит справку.

### Правила проверки параметров

**`--package`.** В режиме `remote` — правила crates.io: от 1 до 64
символов, латинские буквы, цифры, `-` и `_`, первый символ — буква.
В режиме `test` — большие латинские буквы (`A`, `B`, `AB`). Ошибки:
не задан, пустой, длиннее 64 символов, недопустимые символы, не
большие буквы в режиме `test`.

**`--repo`.** В режиме `remote` — URL-адрес со схемой `http` или
`https` и указанным сервером. В режиме `test` — существующий файл,
доступный для чтения. Ошибки: не задан, пустой, другая схема, нет
сервера, пробелы в URL; файл не найден, это каталог, нет прав на
чтение.

**`--mode`.** Только `remote` или `test`, любое другое значение —
ошибка.

**`--version`.** SemVer `X.Y.Z` с необязательными пререлизом и сборкой
(`1.0.0-beta.1`, `2.1.3+build.5`) или `latest` — последняя версия.
Ошибки: пустая, неполная (`1.0`), ведущие нули (`01.0.0`), префикс
`v`, требования Cargo (`^1.0.0`).

**`--output`.** Имя файла с расширением `.svg` (регистр не важен) в
существующем каталоге, доступном для записи. Ошибки: пустое имя,
другое расширение, по этому пути находится каталог, каталог не
существует, нет прав на запись.

**`--filter`.** Необязательный. Непустая подстрока из латинских букв,
цифр, `-` и `_`. Ошибки: пустая подстрока, недопустимые символы
(такая подстрока не совпала бы ни с одним пакетом).

Проверяются все параметры сразу, и все найденные ошибки выводятся за
один запуск. Если режим указан неверно, имя пакета и адрес репозитория
по правилам режима не проверяются (проверяется только, что они
заданы). На этапе 1 к сети не обращаются: проверяется только форма
значений и наличие локальных файлов и каталогов.

Каждая ошибка выводится в стандартный поток ошибок в виде
`ошибка: --опция: описание`, программа завершается с кодом 2.

### Получение прямых зависимостей (режим `remote`)

Репозиторий — sparse-индекс реестра Cargo, например
`https://index.crates.io` (индекс crates.io). Это тот же протокол,
которым пользуется Cargo, но менеджер пакетов и сторонние библиотеки
не используются: файлы загружаются модулем `urllib`, разбираются
модулем `json` из стандартной библиотеки Python.

1. Проверяется, что по URL находится индекс Cargo: в его корне должен
   быть файл `config.json` с полем `dl`. Если указать, например,
   `https://crates.io` (сайт, а не индекс), выводится подсказка.
2. Загружается файл пакета. Путь к нему строится по правилам Cargo,
   имя приводится к нижнему регистру: `1/{имя}` и `2/{имя}` для имён
   из 1–2 символов, `3/{первая буква}/{имя}` для трёх символов,
   `{ab}/{cd}/{имя}` для остальных (`serde` → `se/rd/serde`).
3. Файл содержит по одной JSON-строке на каждую опубликованную версию.
   Выбирается версия из `--version`. Для `latest` берётся наибольшая
   по SemVer неотозванная (не yanked) версия; пререлизы берутся, только
   если других версий нет, — так же выбирает Cargo. Точную версию можно
   получить, даже если она отозвана, это отмечается в выводе.
4. Из выбранной строки берётся список `deps` — прямые зависимости.

Для каждой зависимости выводятся имя, требование к версии из
Cargo.toml (`^1.0`, `=0.2.129`, `~2.3.0`) и пометки:

| Пометка | Значение |
| --- | --- |
| `build`, `dev` | вид зависимости: для сборочного скрипта или только для тестов и примеров (без пометки — обычная) |
| `необязательная` | зависимость подключается только при включении feature |
| `платформа cfg(...)` | зависимость нужна только на указанной платформе |
| `пакет ИМЯ` | зависимость переименована в Cargo.toml, ИМЯ — настоящий пакет в реестре |

Зависимости упорядочены по виду (обычные, build, dev) и имени. Одна и
та же зависимость может встречаться несколько раз — для разных видов
или платформ, так она и записана в индексе.

Ошибки получения данных (код завершения 1): сервер недоступен, по URL
нет индекса Cargo, ошибка HTTP, пакета нет в репозитории, версии нет у
пакета (выводятся пять последних версий), все версии отозваны,
повреждённая строка индекса.

### Тестовый репозиторий (режим `test`)

Файл описывает пакеты с именами из больших латинских букв, по одному
на строку: `ПАКЕТ: ЗАВИСИМОСТЬ ...`. Пакет без зависимостей
записывается с пустым списком. Пустые строки и строки, начинающиеся с
`#`, пропускаются (`examples/test_repo.txt`):

```
A: B C
B: D
C: D E
D:
E:
```

Ошибки файла сообщаются с номером строки: нет двоеточия, имя не из
больших латинских букв, зависимость указана дважды, пакет описан
повторно. Ошибкой также считается пакет, не описанный в файле.
`--version` в тестовом режиме не используется, об этом выводится
предупреждение.

### Вывод и коды завершения

| Код | Значение |
| --- | --- |
| 0 | прямые зависимости выведены в стандартный поток вывода |
| 1 | ошибка получения данных |
| 2 | ошибка в параметрах командной строки |

Сообщения об ошибках и предупреждения выводятся в стандартный поток
ошибок.

## Сборка и запуск

Внешние зависимости отсутствуют, нужен Python 3.8+. Сборка не
требуется. Для режима `remote` нужен доступ в интернет к
`https://index.crates.io`.

```sh
./run.sh --package serde --repo https://index.crates.io     # Linux и macOS
run.bat --package serde --repo https://index.crates.io      # Windows
```

Демонстрационные скрипты (выводят команду, результат и код
завершения):

| Скрипт | Что показывает |
| --- | --- |
| `scripts/demo_deps.sh` (`.bat`) | прямые зависимости: последняя и заданная версия, все пометки, тестовый режим |
| `scripts/demo_data_errors.sh` (`.bat`) | ошибки получения данных и предупреждение о версии в тестовом режиме |
| `scripts/demo_errors.sh` (`.bat`) | обработку ошибок для каждого параметра и нескольких ошибок сразу (этап 1) |

```sh
sh scripts/demo_deps.sh
sh scripts/demo_data_errors.sh
sh scripts/demo_errors.sh
```

Запуск тестов (сеть не нужна: индекс подменяется, HTTP проверяется на
локальном сервере):

```sh
PYTHONPATH=src python3 -m unittest discover -s tests
```

## Примеры использования

Последняя версия пакета:

```

  serde_core =1.0.229
  serde_derive ^1 (необязательная)
```

Заданная версия, все виды пометок:

