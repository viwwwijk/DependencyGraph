# Визуализатор графа зависимостей (вариант №12)

Практическая работа №2 по дисциплине «Конфигурационное управление».

## Общее описание

Инструмент командной строки для построения и визуализации графа
зависимостей пакетов менеджера Cargo (язык Rust). Готовые средства
получения зависимостей (менеджеры пакетов, сторонние библиотеки) не
используются.

Текущее состояние — **этап 5 (визуализация)**, работа выполнена
полностью. Приложение строит граф зависимостей заданного пакета с
учётом транзитивности обходом в ширину (BFS) без рекурсии, не
учитывает пакеты, имя которых содержит подстроку фильтра, корректно
обрабатывает циклические зависимости, выводит **текстовое
представление графа на языке диаграмм Graphviz (DOT)** и сохраняет
**изображение графа в файл SVG**. Граф можно строить по реальному
репозиторию crates.io или по файлу тестового репозитория. Результат
сравнён со штатным инструментом Cargo — `cargo tree` (раздел
«Сравнение с cargo tree»).

Что выводилось на прошлых этапах: на этапе 1 — параметры в формате
`ключ=значение`, на этапе 2 — прямые зависимости пакета, на этапе 3 —
граф списком смежности, на этапе 4 — порядок загрузки зависимостей
(опция `--load-order`). Выводы этапов 1, 2 и 4 по заданию нужны
только на своих этапах, а текстовое представление графа этапа 3
заменено текстом на языке DOT. Состояние после каждого этапа
сохранено в истории и отмечено тегами `stage-1` … `stage-4`
(например, `git checkout stage-4`).

## Описание функций и настроек

### Параметры командной строки

| Опция | Параметр | По умолчанию |
| --- | --- | --- |
| `--package ИМЯ` | имя анализируемого пакета | обязательный |
| `--repo URL\|ПУТЬ` | URL-адрес репозитория или путь к файлу тестового репозитория | обязательный |
| `--mode remote\|test` | режим работы с тестовым репозиторием | `remote` |
| `--version ВЕРСИЯ` | версия пакета | `latest` |
| `--output ФАЙЛ` | имя сгенерированного файла с изображением графа | `graph.svg` |
| `--filter ПОДСТРОКА` | подстрока для фильтрации пакетов | не задана |

Режим `remote` означает работу с реальным репозиторием по URL-адресу,
режим `test` — с файлом тестового репозитория, в котором пакеты
называются большими латинскими буквами. От режима зависят правила
проверки `--package` и `--repo`.

Сокращённые имена опций (например, `--pack`) не принимаются.
`-h`/`--help` выводит справку.

### Правила проверки параметров

**`--package`.** В режиме `remote` — правила crates.io: от 1 до 64
символов, латинские буквы, цифры, `-` и `_`, первый символ — буква.
В режиме `test` — большие латинские буквы (`A`, `B`, `AB`). Ошибки:
не задан, пустой, длиннее 64 символов, недопустимые символы, не
большие буквы в режиме `test`.

**`--repo`.** В режиме `remote` — URL-адрес со схемой `http` или
`https` и указанным сервером. В режиме `test` — существующий файл,
доступный для чтения. Ошибки: не задан, пустой, другая схема, нет
сервера, пробелы в URL; файл не найден, это каталог, нет прав на
чтение.

**`--mode`.** Только `remote` или `test`, любое другое значение —
ошибка.

**`--version`.** SemVer `X.Y.Z` с необязательными пререлизом и сборкой
(`1.0.0-beta.1`, `2.1.3+build.5`) или `latest` — последняя версия.
Ошибки: пустая, неполная (`1.0`), ведущие нули (`01.0.0`), префикс
`v`, требования Cargo (`^1.0.0`).

**`--output`.** Имя файла с расширением `.svg` (регистр не важен) в
существующем каталоге, доступном для записи. Ошибки: пустое имя,
другое расширение, по этому пути находится каталог, каталог не
существует, нет прав на запись.

**`--filter`.** Необязательный. Непустая подстрока из латинских букв,
цифр, `-` и `_`. Ошибки: пустая подстрока, недопустимые символы
(такая подстрока не совпала бы ни с одним пакетом).

Проверяются все параметры сразу, и все найденные ошибки выводятся за
один запуск. Если режим указан неверно, имя пакета и адрес репозитория
по правилам режима не проверяются (проверяется только, что они
заданы). На этапе 1 к сети не обращаются: проверяется только форма
значений и наличие локальных файлов и каталогов.

Каждая ошибка выводится в стандартный поток ошибок в виде
`ошибка: --опция: описание`, программа завершается с кодом 2.

### Построение графа (этап 3)

Граф строится алгоритмом **BFS без рекурсии** (`depviz.graph`):

1. Корневой пакет (`--package` нужной `--version`) кладётся в очередь
   `collections.deque` и в множество уже встреченных пакетов.
2. Пока очередь не пуста, из её начала берётся пакет, загружаются его
   прямые зависимости, для каждой выбирается версия, и записываются
   рёбра. Зависимости, которые ещё не встречались, добавляются в конец
   очереди. Поэтому пакеты обрабатываются по уровням: сначала прямые
   зависимости корня, затем их зависимости и т. д.
3. Каждый пакет попадает в очередь не больше одного раза. Общая
   зависимость нескольких пакетов (ромб) обрабатывается один раз, а
   цикл не приводит к бесконечному обходу: ребро к уже встреченному
   пакету записывается, но пакет повторно не разбирается.

**Фильтр.** Пакет, имя которого содержит подстроку `--filter`
(с учётом регистра), не учитывается: он не попадает в граф, его
собственные зависимости не загружаются. Пакеты, нужные только
исключённым, тоже пропадают из графа, а фильтр может разорвать цикл.
Если фильтр исключает сам анализируемый пакет, выводится ошибка.

**Циклы.** После обхода циклы ищутся поиском в глубину — тоже без
рекурсии, с явным стеком и раскраской вершин: ребро в вершину, которая
ещё в стеке, замыкает цикл. Каждый цикл выводится один раз, включая
петли (пакет зависит сам от себя). В реальном crates.io циклы между
обычными зависимостями невозможны (Cargo их запрещает) — бывают только
через dev-зависимости, которые в граф не входят; поэтому циклы
показываются на тестовом репозитории.

**Какие зависимости учитываются в режиме `remote`:**

| Зависимость | Учитывается | Почему |
| --- | --- | --- |
| обычная, build | да | нужна для сборки пакета |
| dev | нет | нужна только для тестов самого пакета; Cargo не собирает dev-зависимости зависимостей |
| необязательная (optional) | нет | подключается только при включении feature |
| с `cfg(...)`, ложным всегда | нет | например, `cfg(any())`: так serde закрепляет версию serde_derive |
| для отдельной платформы | да | граф строится для всех платформ сразу |

Переименованная зависимость учитывается под настоящим именем пакета.
Условия `cfg` вычисляются в трёхзначной логике (истинно всегда,
ложно всегда, зависит от платформы).

**Выбор версии зависимости.** Для каждой зависимости в индексе указано
требование к версии в формате Cargo. Выбирается наибольшая
неотозванная версия, которая ему удовлетворяет (`depviz.versionreq`):

| Требование | Подходящие версии |
| --- | --- |
| `^1.2.3`, `1.2.3` | `>=1.2.3, <2.0.0` |
| `^0.2.3` / `^0.0.3` | `>=0.2.3, <0.3.0` / `>=0.0.3, <0.0.4` |
| `~1.2.3` / `~1` | `>=1.2.3, <1.3.0` / `>=1.0.0, <2.0.0` |
| `*`, `1.*`, `1.2.*` | любые / `1.x.y` / `1.2.x` |
| `=1.2.3`, `>1.2`, `>=1`, `<2`, `<=1.5` | по сравнению; частичные версии дополняются по правилам Cargo |
| `>=1.0, <1.5` | все условия через запятую одновременно |

Пререлиз подходит, только если в требовании есть пререлиз для тех же
`X.Y.Z`. Файл индекса каждого пакета загружается один раз. Если пакета
нет в индексе или ни одна версия не подходит, зависимость не
добавляется в граф и указывается в комментарии «Не удалось выбрать версию»;
ошибка подключения к серверу прерывает построение.

### Визуализация (этап 5)

После построения графа (этап 3) `depviz.dot` записывает его на языке
диаграмм Graphviz (DOT), а `depviz.render` передаёт этот текст
программе `dot` из пакета [Graphviz](https://graphviz.org), которая
рисует граф и сохраняет изображение в файл `--output` в формате SVG.
Graphviz используется только для рисования: зависимости программа
получает сама.

Как устроен текст DOT:

- `digraph dependencies { ... }` — ориентированный граф; ребро
  `"пакет" -> "зависимость"` означает «пакет зависит от зависимости»;
- идентификатор вершины — имя и версия пакета (`"url 2.5.2"`), подпись —
  имя и версия на двух строках; в тестовом режиме — только имя;
- вершины и рёбра перечисляются в порядке обхода в ширину;
- анализируемый пакет выделен синим цветом и рамкой, рёбра,
  входящие в циклические зависимости, — красным цветом;
- заголовок изображения — «Зависимости пакета ...», при фильтре в
  нём перечислены исключённые пакеты;
- перед графом комментариями `//` записаны итоги: источник данных,
  число пакетов и связей, исключённые фильтром пакеты, циклы и
  зависимости, для которых не удалось выбрать версию.

Специальные символы в именах (кавычки, обратная косая черта)
экранируются. Исключённые фильтром пакеты и пакеты, нужные только им,
в изображение не попадают.

### Получение данных из индекса Cargo (режим `remote`)

Репозиторий — sparse-индекс реестра Cargo, например
`https://index.crates.io` (индекс crates.io). Это тот же протокол,
которым пользуется Cargo, но менеджер пакетов и сторонние библиотеки
не используются: файлы загружаются модулем `urllib`, разбираются
модулем `json` из стандартной библиотеки Python.

1. Проверяется, что по URL находится индекс Cargo: в его корне должен
   быть файл `config.json` с полем `dl`. Если указать, например,
   `https://crates.io` (сайт, а не индекс), выводится подсказка.
2. Загружается файл пакета. Путь к нему строится по правилам Cargo,
   имя приводится к нижнему регистру: `1/{имя}` и `2/{имя}` для имён
   из 1–2 символов, `3/{первая буква}/{имя}` для трёх символов,
   `{ab}/{cd}/{имя}` для остальных (`serde` → `se/rd/serde`).
3. Файл содержит по одной JSON-строке на каждую опубликованную версию.
   Выбирается версия из `--version`. Для `latest` берётся наибольшая
   по SemVer неотозванная (не yanked) версия; пререлизы берутся, только
   если других версий нет, — так же выбирает Cargo. Точную версию можно
   получить, даже если она отозвана, это отмечается в выводе.
4. Из выбранной строки берётся список `deps` — прямые зависимости с
   требованием к версии, видом (normal, build, dev), признаком
   optional, условием платформы и настоящим именем пакета при
   переименовании.

Ошибки получения данных (код завершения 1): сервер недоступен, по URL
нет индекса Cargo, ошибка HTTP, пакета нет в репозитории, версии нет у
пакета (выводятся пять последних версий), все версии отозваны,
повреждённая строка индекса.

### Тестовый репозиторий (режим `test`)

Файл описывает пакеты с именами из больших латинских букв, по одному
на строку: `ПАКЕТ: ЗАВИСИМОСТЬ ...`. Пакет без зависимостей
записывается с пустым списком. Пустые строки и строки, начинающиеся с
`#`, пропускаются (`examples/test_repo.txt`):

```
A: B C
B: D
C: D E
D:
E:
```

Ошибки файла сообщаются с номером строки: нет двоеточия, имя не из
больших латинских букв, зависимость указана дважды, пакет описан
повторно. Пакет, до которого доходит обход, должен быть описан в
файле, иначе выводится ошибка; пакет, исключённый фильтром, описывать
не обязательно. `--version` в тестовом режиме не используется, об этом
выводится предупреждение.

Тестовые репозитории для разных случаев (`examples/graphs/`):

| Файл | Случай |
| --- | --- |
| `bfs_order.txt` | несколько уровней — порядок обхода в ширину; пакет X недостижим из A |
| `diamond.txt` | ромб: общая зависимость двух пакетов |
| `cycles.txt` | циклы `A -> B -> C -> A`, `D -> E -> D` и петля `F -> F` |
| `filter.txt` | многобуквенные имена для фильтра по подстроке |
| `layers.txt` | несколько слоёв зависимостей |
| `partial_cycle.txt` | цикл `C -> E -> C` только в одной ветви графа |
| `missing.txt` | зависимость, не описанная в файле |

### Вывод и коды завершения

| Код | Значение |
| --- | --- |
| 0 | граф выведен на языке DOT, изображение сохранено в файл SVG |
| 1 | ошибка получения данных |
| 2 | ошибка в параметрах командной строки |
| 3 | не удалось сохранить изображение (нет Graphviz или ошибка `dot`) |

Текст графа на языке DOT выводится в стандартный поток вывода, а
сообщение о сохранённом файле, предупреждения и ошибки — в
стандартный поток ошибок. Поэтому текст графа можно сохранить в файл:
`./run.sh ... > graph.dot`. Если Graphviz не установлен, текст DOT
всё равно выводится, а программа завершается с кодом 3 и подсказкой,
где скачать Graphviz.

### `depviz.validators`

| Функция | Назначение |
| --- | --- |
| `validate_mode(mode)` | проверить режим работы |
| `validate_package(name, mode)` | проверить имя пакета по правилам режима |
| `validate_repo(repo, mode)` | проверить URL-адрес или файл тестового репозитория |

Каждая функция возвращает текст ошибки или пустую строку.

## Сборка и запуск

Нужен Python 3.8+ (сторонние библиотеки не используются) и
[Graphviz](https://graphviz.org/download/) для сохранения изображения
(программа `dot` должна быть в `PATH`; Ubuntu: `sudo apt install
graphviz`, macOS: `brew install graphviz`, Windows: установщик с
сайта). Сборка не требуется. Для режима `remote` нужен доступ в
интернет к `https://index.crates.io`.

```sh
./run.sh --package serde --repo https://index.crates.io     # Linux и macOS
run.bat --package serde --repo https://index.crates.io      # Windows
```

Демонстрационные скрипты (выводят команду, результат и код
завершения; изображения сохраняются в каталог `out/`):

| Скрипт | Что показывает |
| --- | --- |
| `scripts/demo_visualize.sh` (`.bat`) | визуализацию трёх пакетов crates.io, tokio с фильтром и тестовых графов |
| `scripts/demo_compare_cargo_tree.sh` (`.bat`) | сравнение с `cargo tree` и изображения обоих графов (нужен Cargo) |
| `scripts/demo_data_errors.sh` (`.bat`) | ошибки получения данных и предупреждение о версии в тестовом режиме |
| `scripts/demo_errors.sh` (`.bat`) | обработку ошибок для каждого параметра и нескольких ошибок сразу (этап 1) |

sh scripts/demo_visualize.sh
sh scripts/demo_compare_cargo_tree.sh
sh scripts/demo_data_errors.sh

Тесты, которые запускают настоящий Graphviz, пропускаются, если он не

## Сравнение с cargo tree

Штатный инструмент Cargo для просмотра зависимостей — команда
[`cargo tree`](https://doc.rust-lang.org/cargo/commands/cargo-tree.html):
она выводит зависимости пакета текстовым деревом. Скрипт
`scripts/compare_with_cargo_tree.py` создаёт пустой проект Cargo,
зависящий от пакета crates.io точной версии, выполняет для пакета

```sh
cargo tree -p ПАКЕТ@ВЕРСИЯ --target all -e normal,build
```

(для всех платформ, обычные и build-зависимости — то же, что учитывает
depviz), выводит это дерево, превращает его в граф и сравнивает
пакеты и связи с графом depviz. Если указан каталог, в него
сохраняются изображения обоих графов, нарисованные одинаково, —
`ПАКЕТ-depviz.svg` и `ПАКЕТ-cargo-tree.svg`. Cargo
(https://rustup.rs) нужен только этому скрипту; сам depviz менеджер
пакетов не использует.

```sh
PYTHONPATH=src python3 scripts/compare_with_cargo_tree.py regex 1.10.5 out
sh scripts/demo_compare_cargo_tree.sh        # четыре пакета сразу
```

Результаты (Cargo 1.97.0):

| Пакет | depviz: пакетов / связей | cargo tree: пакетов / связей | Итог |
| --- | --- | --- | --- |
| url 2.5.2 | 7 / 7 | 7 / 7 | совпадают |
| tokio 1.38.0 | 13 / 12 | 13 / 12 | совпадают |
| serde_json 1.0.120 | 5 / 4 | 10 / 13 | у cargo tree лишние serde_derive, proc-macro2, quote, syn, unicode-ident |
| regex 1.10.5 | 3 / 2 | 5 / 8 | у cargo tree лишние aho-corasick, memchr и 6 связей |

Связей, которые есть только в depviz, не нашлось ни для одного пакета:
всё, что показывает depviz, показывает и `cargo tree`. Причины
расхождений:

1. **Дерево и граф.** `cargo tree` выводит дерево: пакет, который
   нужен нескольким пакетам, печатается несколько раз, а пометка `(*)`
   означает, что его зависимости уже показаны выше (у regex `memchr`
   встречается трижды). depviz рисует граф: каждый пакет — одна
   вершина, в которую входят рёбра от всех зависящих пакетов. Это
   разная форма одной информации; чтобы сравнить, скрипт превращает
   дерево в граф. Кроме того, `cargo tree` выводит только текст, а
   depviz сохраняет изображение.
2. **Условие `cfg(any())` (serde_json).** serde_core зависит от
   serde_derive под условием `cfg(any())`, которое никогда не бывает
   истинным: так закрепляется версия serde_derive, но сама
   зависимость не собирается (на этапе 4 `cargo build` её не собирал).
   `cargo tree --target all` показывает зависимости всех платформ, не
   вычисляя условия, поэтому выводит serde_derive и пять его
   зависимостей. depviz вычисляет `cfg` и отбрасывает всегда ложные
   условия.
3. **Features и необязательные зависимости (regex).** Cargo включает
   features по умолчанию, и они подключают необязательные
   (optional) зависимости: у regex это aho-corasick и memchr, а
   regex-automata через feature `syntax` получает regex-syntax.
   depviz features не моделирует и необязательные зависимости не
   учитывает (см. этап 3), поэтому таких пакетов и связей у него нет.
4. **Платформы (tokio).** С `--target all` графы tokio совпадают,
   включая backtrace под пользовательским условием
   `cfg(tokio_taskdump)`. Без этой опции `cargo tree` показывает
   зависимости только для текущей платформы, и для tokio выводит
   лишь pin-project-lite. depviz всегда строит граф для всех платформ.
5. **Выбор версий.** `cargo tree` берёт версии из `Cargo.lock`
   (одна версия на совместимый диапазон для всего проекта), depviz —
   наибольшую подходящую версию для каждого требования. На
   проверенных пакетах версии совпали, но в общем случае могут
   различаться.

Сравнение порядка загрузки с `cargo build` (этап 4) описано в
README версии `stage-4`.
